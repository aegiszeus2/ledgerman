1. What Is Ledgerman?

Ledgerman is a multi-tenant SaaS construction management platform. Each customer company gets a fully isolated workspace where their admin manages projects, workers, and invoices — and workers clock in/out, submit time entries, photos, and expenses from any device.

👷

Workers

Clock in/out, submit time, log expenses, upload photos. PIN login with optional 2FA. Mobile-optimized.

⚙️

Admin / PM

Manage projects, clients, workers, approve time entries, generate invoices, run reports.

✅

Approver

Worker with elevated role. Can access the admin panel to approve/reject time submissions without full admin access.

🛡️

LittleShield (Lucas)

Super-admin console. Manages all company subscriptions, runs automated diagnostics, supports customers.

7. User Instructions by Role

🛡️ Lucas — Product Owner (Super Admin)

  1. Start the backend: cd ledgerman-backend && python3 server.py
  2. Open ledgerman-admin/index.html in browser — enter key from .superadmin_key
  3. Use Overview tab to see all active companies and revenue
  4. Use Companies tab to view any company's workers, activity, and detail
  5. Use 🛡️ LittleShield tab to run automated diagnostics on any customer — scores them 0–100 and flags issues
  6. Use Support tab to generate onboarding messages for new customers
  7. To onboard a new customer: send them the Netlify app URL — they self-register
  8. To delete a company (cancelled subscription): click 🗑 in the Companies tab

⚙️ Company Admin / PM

  1. First time: Open the app URL → click "Get Started" → enter company name + admin password → saved
  2. Returning: Open URL → Admin Login → enter password
  3. Go to Settings → complete company info (name, address, HST number, invoice prefix)
  4. Go to Workers → Add workers → click Invite → share the link or QR code with each worker
  5. Go to Projects → Create projects → assign clients, add subtasks
  6. Workers submit time → go to Approvals → review and Approve or Reject
  7. Go to Invoices → Create invoice from approved time → Print PDF for client
  8. Go to Reports → view cost summaries, labour by worker, project totals
  9. Second device: Open app → "Get Started" → "Link Existing" tab → enter Company ID + password
⚠️ Company ID: Found in Settings. Share it with anyone who needs to access your company from another device using admin login.

👷 Worker

  1. First time: Click the invite link sent by your admin (or scan QR code)
  2. Choose a 4–6 digit PIN → optionally enable 2FA (scan QR with Google Authenticator / Authy)
  3. Add your email when prompted → click Save & Continue
  4. Returning: Open the app URL → Worker Login → enter your PIN
  5. From Home screen → tap a project → choose Clock In / Clock Out or Manual Entry
  6. Clock In: tap Clock In at start of shift → tap Clock Out at end → hours auto-rounded to nearest 15 min
  7. Manual Entry: enter start/end times and a description → Submit
  8. To add an expense: go to the project → Expense tab → fill in amount, description, upload receipt photo
  9. Check your History tab to see all past submissions and their approval status

✅ Approver (elevated Worker)

  1. Login at Admin Login screen using your worker PIN (not password)
  2. You have access to the Approvals section only
  3. Review pending submissions — you can see whether time was clocked in/out (⏱) or manually entered (✏️)
  4. Click Approve or Reject with a note

9. Data Flow — Multi-Device Sync

  Device A (Admin)          Backend (Flask + SQLite)         Device B (Worker)
  ─────────────────         ─────────────────────────         ─────────────────
  1. Login (password)  →    POST /api/auth/admin
                       ←    { token: "JWT..." }

  2. Load data         →    GET /api/sync
                       ←    { workers: [...], projects: [...], ... }
                            (populates in-memory cache)

  3. Create project    →    POST /api/projects { name, ... }
                       ←    { id: "abc123", ... }
                            (cache updated + localStorage backup)

                                                    4. Worker login    →    POST /api/auth/worker
                                                                       ←    { token: "JWT..." }

                                                    5. Sync            →    GET /api/sync
                                                                       ←    sees the new project ✓

                                                    6. Submit time     →    POST /api/submissions
                       ←    (badge on Approvals tab updates next sync)
ℹ️ The frontend cache updates instantly on writes (so the UI feels fast), then pushes to the API in the background. On login, a full sync always loads the latest server state.

13. Backup & Recovery

⭐ MASTERBACKUP.zip — The One File You Need

Location: ~/Desktop/Project Organizer/ledgerman/MASTERBACKUP.zip

This is the single canonical backup of the entire Ledgerman system. It contains all source code, the live database, the super-admin key, all launch scripts, and documentation. To move, restore, or hand off Ledgerman — copy only this file.

  • Auto-overwritten every night at 2:00 AM by cron (always fresh)
  • ~200KB — small enough to email, USB, or cloud-share instantly
  • To restore: unzip → bash ledgerman-backend/SETUP.sh → ./START-ALL.sh

Automated Backup System

  • Daily backups: ledgerman-backups/daily/ — timestamped zips, 30-day retention (auto-pruned)
  • Monthly backups: ledgerman-backups/monthly/ — one per month, 12-month retention
  • Log: ledgerman-backups/backup.log — every run recorded with size + file count
  • Cron schedule: 0 2 * * * — runs daily at 2AM automatically
  • Manual trigger: bash LEDGERMAN-BACKUP.sh from Project Organizer folder

What's Included in Every Backup

  • ledgerman-backend/ledgerman.db — live database (all company data)
  • ledgerman-backend/.superadmin_key — LittleShield access key
  • ledgerman-backend/server.py, database.py, auth.py, requirements.txt
  • ledgerman/app/ — full frontend source
  • ledgerman/LEDGERMAN-SYSTEM-GUIDE.html — this document
  • ledgerman-admin/index.html — LittleShield console
  • START-ALL.sh, START-ALL.bat, README-NEW-MACHINE.txt

Restore Procedure (New Machine)

  1. Copy MASTERBACKUP.zip to the new machine's Desktop
  2. Unzip it — this recreates the full Project Organizer/ folder structure
  3. Run bash ledgerman-backend/SETUP.sh — installs Python dependencies, restores DB
  4. Run ./START-ALL.sh — backend starts on port 5001, frontend on 8765
  5. Open http://localhost:8765 — all data is live immediately (database was in the backup)
  6. See README-NEW-MACHINE.txt for full platform-specific instructions
